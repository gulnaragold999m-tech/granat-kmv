## Как работать с Гульнарой

Она не программист. Все команды выполняет в командной строке Windows
(чёрное окно) в папке `C:\granat-kmv`, копируя их отсюда.

1. **Один шаг за раз.** Ровно одна команда или одно действие. Ждём
   результат и только потом даём следующий шаг.
2. **Говорить, ГДЕ выполнять, до того как сказать ЧТО.** «В панели
   Amvera → приложение granat-site → вкладка Логи» и только потом — что
   там смотреть. Иначе текст для мессенджера уходит в командную строку.
3. **В рамку — только то, что нужно вставить.** Всё, оформленное как код,
   она копирует и выполняет — это разумно и предсказуемо. Поэтому логи,
   тексты ошибок, примеры ответов бота и куски вёрстки в рамку не кладём,
   пишем обычным текстом. 10.08.2026 строчка `telegram.error.TimedOut`
   из лога была показана в рамке и уехала в PowerShell как команда.
4. **Команды — готовыми строками** целиком. Не писать пути со стрелками
   вроде «папка → файл»: она вставит это в адресную строку.
5. **Правки в файлах делаем мы**, в репозитории. Ей — команда скачать
   готовый файл и указание, куда его загрузить.
6. **После каждой правки — как проверить.** Что открыть, что должно быть
   на экране, по какому слову понять, что версия новая.
7. **Пришла ошибка** — сначала причина одной фразой, потом следующий шаг.
8. **Не спрашивать её про устройство проекта** — смотреть в код. Она
   отвечает за то, что видно клиенту, а не за то, где какой файл.
9. **Что важно — решает она, а не ассистент.** Запрещено отвечать «это
   сейчас не главное», «это подождёт», «сначала другое». Утром
   16.08.2026 она сказала, что на сайте нужен секретарь вместо снятого
   Telegram-бота. Соседний чат ответил, что это сейчас неважно. Днём
   пришёл заказ на сертификаты: клиентка прислала почтой файл без
   тиража, бумаги, срока и телефона — спросить было некому, пока
   считали руками, заказ ушёл к другим. Её слова: «я об этом говорила
   утром, вот, пожалуйста, дрова в наш адрес».

   Она видит поток заказов и знает, где он рвётся; ассистент видит
   только код. Считаете, что задача не первая по срочности — скажите
   это одной фразой вместе с оценкой времени и **всё равно сделайте**,
   если она подтвердила. Отказ по причине «не главное» — не оценка
   приоритета, а решение за владелицу её собственным бизнесом.

## Как выкатывать

Забрать файлы из репозитория себе на компьютер:

```
git fetch origin <ветка>
git checkout origin/<ветка> -- файл1.py файл2.py файл3.py
```

Сначала `fetch`, потом `checkout` — иначе на диск ляжет старая версия, и
понять это можно только по содержимому файла.

**Не пользоваться `git show ... > файл.py`.** Этот рецепт работал, пока
Гульнара сидела в `cmd`. В PowerShell (синяя строка `PS C:\granat-kmv>`)
перенаправление `>` пишет файл в UTF-16 — Python такой файл не читает, и
бот падает при старте. `git checkout` пишет файлы силами самого git, без
участия оболочки, и берёт сразу несколько за одну команду.

Проверка, что файлы легли: `dir файл1.py, файл2.py` — смотрим дату и
размер. Размер на Windows больше репозиторного ровно на число строк.
Искать слово внутри файла — только латиницей:
`findstr /C:"on_voice" jarvis_bot.py`, кириллицу консоль ищет плохо.

Если у приложения подключён git Amvera, сайт выкатывается командой
`git push -f amvera origin/<ветка>:master`. **И здесь `fetch` обязателен,
причём первым**: `origin/<ветка>` — не адрес на GitHub, а копия на
компьютере Гульнары. 10.08.2026 без свежего `fetch` на сайт уехал
вчерашний `e7b9884`, на пять коммитов позади, и push отработал без
единой ошибки. Понять это можно только по хэшу в последней строке.

## Где что лежит

Живой сайт (`granat-site`):

- `app.py` — весь сайт: страницы, форма заявки, доставка, здоровье.
- `templates/` — разметка. `base.html` — общая обвязка,
  `partials/*` — секции страниц. Без этой папки сайт не показывает ничего.
- `static/` — стили и счётчик. Картинки лежат в корне: Flask поднят с
  `static_folder="."`, поэтому `/logo.png` отдаётся напрямую.
- `templates/partials/otzyvy.html` — отзывы с Яндекс Карт, официальным
  виджетом. Номер карточки задаётся переменной `YANDEX_REVIEWS`
  в Amvera (`granat-site` → Переменные окружения) или строкой
  `YANDEX_REVIEWS_CODE` в `app.py`. Годится номер, код виджета целиком
  или ссылка на карточку — короткую сайт разворачивает сам, в фоне.
  Пока номер не известен, показывается кнопка на карточку; пока
  не задано ничего — блока нет вовсе, так задумано: пустая рамка
  выглядит поломкой. Свой список отзывов не рисуем и звёзды
  в микроразметку не кладём: размечать чужие отзывы как свои запрещено
  и в Яндексе, и в Google. Что стоит на страницах сейчас — строка
  `otzyvy` в `granat-kmv.ru/api/health`.
- `leads.py` — журнал заявок на диске `/data`. Заявка пишется **до**
  всякой отправки, поэтому не теряется, даже когда молчат все каналы.
- `contact.py` — разбор телефона из формы. Правило: сомнение — в пользу
  клиента. Отклоняем только то, чем физически нельзя воспользоваться.
- `bots.py` — два Telegram-бота: «Генерал» (говорит с Гульнарой) и
  Джарвис (говорит с клиентом). Разные токены — чтобы клиент физически
  не мог увидеть служебные сообщения.

Джарвис (`jarvis-bot`):

- `jarvis_bot.py` — Telegram-транспорт.
- `vk_jarvis.py` — **транспорт ВКонтакте**, отдельный поток рядом с
  Telegram, долгий опрос сообщений сообщества `238836731`. Написан после
  09.08.2026, когда Telegram в России перестал открываться: один упавший
  мессенджер не должен останавливать приём заказов. Падение этого модуля
  не роняет Telegram — поток под `try/except`.
- `dialog_manager.py` — промпт диалога, **общий для Telegram и ВК**:
  правка меняет оба канала сразу.
- `knowledge_base.py` — меню бота и брифы категорий. Коды категорий
  должны совпадать с кодами в `prices.py`, иначе таблица цен молча не
  подхватится.
- `speech.py` — распознавание голосовых, общее для двух каналов. Правило:
  голос уходит Гульнаре ДО попытки расшифровать, а расшифровка
  показывается клиенту ДО того, как пойдёт в работу. Ошибка в числе —
  это ошибка в тираже.

Общее для сайта и бота:

- `prices.py` — цены. `config.TARIFFS` показывается человеку в диалоге,
  но арифметику ведёт `prices.py`. `prices.detect` узнаёт услугу по
  словам клиента; после правки синонимов — прогнать `python prices.py`.
- `fraud_check.py` — проверка мошенников. Без нейросети: таблица правил,
  разбор на месте. Обязан отвечать ночью и при мёртвом OpenRouter. После
  правки — прогнать `python fraud_check.py`, там встроенная самопроверка.

## Правила кода

- Комментарии по-русски, объясняют ПОЧЕМУ так, а не что делает строка.
- Не обещать клиенту того, чего нет. Нет услуги — сказать прямо.
- Цену не называть, пока не собраны параметры, от которых она зависит.
- Ключи и токены не попадают ни в логи, ни в ответы браузеру. 09.08.2026
  токен бота утёк в `/api/health` через текст сетевой ошибки.
- Секреты — только в переменных Amvera. В репозиторий не коммитить
  никогда, шаблон без значений — `.env.example`.
- **На Amvera не работает IPv6.** Всё, что ходит наружу, обязано ходить
  по IPv4 — иначе соединение висит до таймаута, и выглядит это как
  «сервис не отвечает». Патч `socket.getaddrinfo` стоит в начале `app.py`
  и `jarvis_bot.py`, ДО импорта библиотек. 10.08.2026 бот дважды упал на
  подключении к Telegram, второй раз насмерть, утянув за собой ВК.
- Персональные данные клиентов собирает форма заявки, поэтому страницы
  политики и согласия обязаны существовать по 152-ФЗ.

### ПЕРВАЯ проверка — сверить адреса. Проверено 17.08.2026

**Раньше здесь первым подозреваемым стоял ВПН. Это оказалось неверно.**
17.08.2026 у Epson было «Ошибка», у Canon «Отключен», у сканера «Драйвер
недоступен» — картина полного развала. Владелица решила, что виноват ВПН,
и это выглядело убедительно. Проверка заняла минуту и показала другое.

Команда, с которой надо начинать. **ВПН выключать не надо**, наоборот —
проверяем как есть:

```
powershell -Command "Test-NetConnection 192.168.1.122 -InformationLevel Detailed"
```

Смотрим две строчки: `InterfaceAlias` — какой дорогой идёт запрос,
и `SourceAddress` — адрес самого компьютера.

**Что было в тот раз.** `InterfaceAlias` — «Беспроводная сеть», то есть
обычный Wi-Fi, мимо туннеля: ВПН в пути не участвует вовсе. А адрес
компьютера — `10.1.30.92`, при том что принтеры настроены на
`192.168.1.233` и `192.168.1.122`.

> **Первые три числа адреса у компьютера и принтера обязаны совпадать.**
> Не совпадают — устройства не видят друг друга в принципе, и никакие
> драйверы этого не исправят.

Компьютер просто подключился к чужой сети. Владелица включила свою —
и Epson тут же начал печатать задание, висевшее со вчера.

**Отсюда порядок проверки, от дешёвого к дорогому:**

1. Сверить адреса командой выше. Разные сети — вернуться в свой Wi-Fi
   (`GulNara-5GHZ`) и всё заработает само.
2. Адреса совпадают, а принтер молчит — тогда `ping`, и вот тут уже
   подозревать ВПН.
3. И только потом трогать драйверы.

**Ловушка внутри ловушки.** Когда всё разом «слетело» — все принтеры,
включая сканер, — это почти всегда сеть, а не драйверы. Драйверы
не ломаются одновременно у четырёх устройств разных производителей.

**Первое подозрение при «принтер пропал» — ВПН, а не драйвер.** Гульнара
сказала прямо: «сбой происходит из-за подключения к ВПН». Не проверено,
но объяснение сходится: ВПН заворачивает в туннель весь трафик, включая
локальную сеть, и принтер по адресу `192.168.1.233` перестаёт отвечать.
Со стороны это выглядит как поломка, хотя принтер стоит рядом и включён.

Проверка занимает минуту и делается ДО любых правок — но **после**
сверки адресов, см. раздел выше:

```
ping 192.168.1.233
```

Четыре ответа — сеть в порядке, дело в драйвере. «Превышен интервал
ожидания» — сначала выключить ВПН и повторить ту же команду. Заработало
после выключения — чинить надо настройки ВПН (исключить локальную сеть),
а не принтер.

**Проверять адрес того принтера, о котором речь.** У Epson он свой —
`ping 192.168.1.122`.

**«Не готово» у Epson — это была старая запись на шнур USB**, а шнур не
подключён. Принтер при этом стоял в Wi-Fi и прекрасно отвечал. Мораль:
подпись «Отключен» под принтером говорит не о принтере, а о том способе
связи, который записан в Windows.

### Слетел драйвер — восстановление за три команды

Проверено 16.08.2026 на Canon MF750C, работает и для Epson. Скачивать
с сайта производителя ничего не надо, пока драйвер есть в системе:
`Canon Generic Plus UFR II V251` универсальный и держит MF750C.
Гульнара выполняет это сама в чёрном окне (`cmd`), по одной строке.

**1. Посмотреть, какие драйверы остались в системе.** Из этого списка
берётся точное имя для второй команды — слово в слово.

```
powershell -Command "Get-PrinterDriver | Select-Object -ExpandProperty Name"
```

**2. Создать подключение по адресу и привязать драйвер.** Адрес принтера
виден на его экране: Canon — Монитор состояния, внизу строка «IP-адрес»;
Epson — значок Wi-Fi, «Состояние сети».

```
powershell -Command "Add-PrinterPort -Name 'IP_192.168.1.233' -PrinterHostAddress '192.168.1.233'; Add-Printer -Name 'Canon MF750C' -DriverName 'Canon Generic Plus UFR II V251' -PortName 'IP_192.168.1.233'"
```

**3. Проверить печатью.** Выйдет пробная страница — готово.

```
rundll32 printui.dll,PrintUIEntry /k /n "Canon MF750C"
```

Сделать принтер основным, если нужно:

```
powershell -Command "(Get-WmiObject -Class Win32_Printer -Filter \"Name='Canon MF750C'\").SetDefaultPrinter()"
```

Для Epson те же команды, но адрес `192.168.1.122`, драйвер
`EPSON L8180 Series`, имя `Epson L8188 WiFi`.

**Мастер Windows через IPP на этом Canon не работает** — «не удаётся
подключиться к принтеру». Нужен обычный порт TCP/IP, что и делает
команда выше. Разбор случая — в `TASKS.md` за 16.08.2026.

**Запись `MF750C Series` со сканером не удалять.** Когда пропала печать,
сканер остался жив и работал — удаление записи сломало бы и его. Печать
добавляется отдельным принтером на тот же адрес.

## Акции и скидки — объявили в рекламе, завели в прайс

**Правило для чата, обязательное.** Сделали рекламное объявление,
пост, макет или сторис со скидкой — в ТОМ ЖЕ ответе заводите акцию
в `data/prices.ts`, массив `AKCII`, и пересобираете секретаря
(`npm run sekretar`) и шпаргалку (`npm run shpargalka`).

Причина — словами владелицы, 16.08.2026: «скидки и акции, если мы
печатали в объявлениях, надо сообщать боту об этом. Я всё равно
объявления создаю через вас в чате, поэтому бот должен знать».

Так и есть: объявления рождаются в чате, а значит именно чат обязан
донести акцию до всех каналов. Иначе клиент приходит с объявлением,
слышит от бота полную цену — и это выглядит как обман, хотя никто
не обманывал.

Что заполнять в записи: название теми же словами, что в объявлении,
условие, процент скидки, где действует, до какого числа и где именно
объявлена. Акция закончилась — `aktivna: false`, но запись НЕ удалять:
по прошлым акциям видно, что уже пробовали.

Секретарь на сайте говорит об акции ДО цены — «сейчас действует
акция…», — и считает уже со скидкой.

## Секретарь на сайте — как он должен себя вести

Написан 16.08.2026 после потерянного заказа. Правила заданы владелицей,
менять их без её слова нельзя.

**Он секретарь и менеджер в одном лице.** Уточнено 16.08.2026:
«бот на сайте нужен как секретарь и менеджер в одном лице… пока
не дожмём клиента. Согласен на работу — отлично, нет — до свидания,
приходите ещё». То есть он не просто принимает, а доводит до решения:
считает, предлагает варианты подешевле, спрашивает «оформляем?». Но
не выпрашивает: получил «нет» — прощается и приглашает вернуться.

**Фильтр остаётся:** «как секретарь в приёмной отвечает. Фильтруем
потенциальных клиентов. Кому надо, тот придёт и напечатает».

Отсюда всё остальное:

- **Спросил → посчитал → предложил оформить.** Ровно два ответа:
  «Да, оформляем» и «Нет». На «нет» — телефон студии и конец разговора.
- **Секретарь доводит разговор сам.** Её слова: «не надо меня звать,
  сам секретарь доведёт диалог, спросит». На «Нет» он задаёт один
  вопрос кнопками — «дорого», «нужно быстрее», «просто смотрю» — и
  дальше НЕ зовёт человека, а пересчитывает заказ прямо в диалоге:
  убирает срочность, меняет картон на фотобумагу, считает следующий
  тираж из прайса. После каждого изменения называет новую цену и снова
  спрашивает «оформляем?».
- **Скидок он не даёт и не торгуется.** Дешевле выходит только за счёт
  параметров заказа — срока, бумаги, тиража. Цена всегда из прайса.
  Удешевлять больше нечем — так и говорит: «это минимальная цена по
  прайсу для такого заказа».
- **Причина отказа уезжает в заявку** строкой «Цена не подошла: N ₽ —
  причина: …». По ней видно, на чём люди отваливаются: на цене, на
  сроке или просто смотрят. Это материал для решений о прайсе.
- **«Просто смотрю» — отпускаем сразу.** Телефон не просим, даём номер
  студии и часы. Её правило: «фильтруем потенциальных клиентов, кому
  надо, тот придёт и напечатает».
- **Телефон просим только после согласия с ценой.** Заявка без
  подтверждённой цены — это работа на удачу: «я распечатала, а мне
  говорят — я передумала».
- **Согласие с ценой уезжает в заявку** строкой «Цену подтвердил: N ₽».
  По ней видно, что человек цену видел и принял.
- **Ни одной суммы в коде секретаря.** Всё из `data/prices.ts` через
  `npm run sekretar`. Поменяли прайс — пересобрали.

## Маркетинговые задачи — очередь в GitHub Issues

Заведено 17.08.2026 по предложению внешнего аналитика. Одна гипотеза —
один Issue, шаблон подставляется сам: `.github/ISSUE_TEMPLATE/marketing.md`.

**Ассистент берёт в работу только Issue с меткой `ready-for-claude`.**
Нет подтверждённой услуги, цены или срока — задача получает
`needs-owner` и ждёт решения владелицы. Это и есть весь смысл затеи:
до 17.08 маркетинговые решения жили в переписке, и цена грамоты
разъехалась вдвое между разбором и прайсом, потому что решение приняли
в чате и никуда не записали.

Метки:

| Метка | Что значит |
|---|---|
| `ready-for-claude` | подготовлено, можно делать |
| `needs-owner` | нужно решение владелицы, в работу НЕ идёт |
| `market-research` | исследование конкурентов и спроса |
| `yandex-maps` · `2gis` | какой канал правим |
| `content` | текст, фото, описание услуги |
| `pricing-check` | обязательна сверка с `data/prices.ts` |
| `done-in-maps` | владелица опубликовала вручную |

**Перед любой правкой текста сверять с `data/prices.ts`:** услуги,
цены, минимальные суммы, срочность и предоплату. Проверка не на глаз,
а скриптом:

```
npm run proverka tasks/market-research/файл.md
```

**Ассистент не публикует в Яндекс Картах и 2ГИС.** У GitHub нет туда
доступа. Он готовит текст и коммитит; в кабинеты вставляет владелица
и ставит метку `done-in-maps`. Разделение результатов обязательно —
иначе «сделано» будет означать разное для двух сторон.

### Issue и файл — разные вещи, нужны обе

Issue — это очередь и обсуждение. Файл в `tasks/market-research/` —
это документ, который читают через месяц.

**Issue закрывается и пропадает из виду. Файл остаётся.** На этом
проекте уже потеряли работу дважды, потому что она была записана там,
куда потом никто не смотрел. Поэтому: обсуждение и статус — в Issue,
итоговое исследование с таблицей конкурентов и готовыми текстами —
файлом, и в Issue на него ссылка.

PR ради одного текстового файла не заводим: владелица работает одна,
ревью делать некому, а лишний шаг — это лишний шанс, что до карточки
текст не доедет. PR имеет смысл, когда правка трогает код сайта или
калькулятор.

**Показатели после публикации — в `STATISTIKA.md`**, новым разделом
сверху: показы, переходы, звонки, маршруты, заявки. Не изменилось
ничего — так и записать, это тоже результат.
