## Как работать с Гульнарой

Она не программист. Все команды выполняет в командной строке Windows
(чёрное окно) в папке `C:\granat-kmv`, копируя их отсюда.

1. **Один шаг за раз.** Ровно одна команда или одно действие. Ждём
   результат и только потом даём следующий шаг.
2. **Никакой теории.** Не объясняем, как устроен git. Говорим, что
   вставить и что должно получиться.
3. **Команды — готовыми строками** целиком. Не писать пути со стрелками
   вроде «папка → файл»: она вставит это в адресную строку и получит
   ошибку. Так уже было.
4. **Правки в файлах делаем мы**, в репозитории. Ей — команда скачать
   готовый файл и указание, куда его загрузить.
5. **После каждой правки — как проверить.** Что открыть, что должно быть
   на экране, по какому слову понять, что версия новая.
6. **Пришла ошибка** — сначала причина одной фразой, потом следующий шаг.

## Главная ловушка проекта: два приложения

`granat-site` (сайт) и `jarvis-bot` (Джарвис) — РАЗНЫЕ приложения Amvera.
У каждого свой git и свой диск `/data`.

**Правка в этом репозитории сама в бота не попадает.** Файл нужно скачать
и загрузить в приложение `jarvis-bot` через его страницу «Репозиторий».
09.08.2026 на этом споткнулись трижды: код лежал в репозитории, а бот
работал по-старому, и это выглядело как «правка не сработала».

Порядок выкатки:

```
git fetch origin <ветка>
git show origin/<ветка>:имя_файла.py > имя_файла.py
```

Сначала `fetch`, потом `show` — иначе `show` запишет старую версию, и
проверить это можно только по содержимому файла. Проверять латиницей:
`findstr /C:"уникальное_слово" файл.py` — кириллицу консоль ищет плохо.

Сайт выкатывается иначе, командой:
`git push -f amvera origin/<ветка>:master`

## Где что лежит

- Цены — только в `prices.py`. `config.TARIFFS` показывается человеку в
  диалоге, но арифметику ведёт `prices.py`.
- Меню бота и брифы категорий — `knowledge_base.py`. Коды категорий там
  должны совпадать с кодами в `prices.py`, иначе таблица цен молча не
  подхватится.
- Промпт диалога — `dialog_manager.py`. Он общий для Telegram и ВК:
  правка меняет оба канала сразу.
- ВК-транспорт — `vk_jarvis.py`, крутится отдельным потоком внутри
  приложения `jarvis-bot`.
- Проверка мошенников — `fraud_check.py`. Тоже общий для двух каналов, но
  без нейросети: таблица правил, разбор на месте. Он обязан отвечать
  ночью и при мёртвом OpenRouter. После правки правил — прогнать
  `python fraud_check.py`, там встроенная самопроверка.
- Незакрытые хвосты и порядок действий по ним — `TASKS.md`.

- Не обещать клиенту того, чего нет. Если услуги нет — сказать прямо.
