## Сменить токен бота «Генерал» — обязательно

09.08.2026 токен несколько часов был виден на открытой странице
`/api/health`: проверка ботов отдавала текст сетевой ошибки как есть, а
Telegram кладёт в него полный адрес запроса вместе с токеном. Утечку
закрыли в тот же день (коммит «Токен бота больше не утекает в /api/health»),
но сам токен считаем скомпрометированным: кто успел его скопировать, тот
может читать заявки.

Что сделать, когда откроется Telegram:
1. @BotFather → `/revoke` → выбрать бота → получить новый токен.
2. Amvera → granat-site → Переменные окружения → `TELEGRAM_BOT_TOKEN`
   (и `ADMIN_BOT_TOKEN`, если заведён) → вставить новый.
3. Открыть `/api/health` и убедиться, что `telegram: ok`.

Старый токен после `/revoke` перестаёт работать сам — отдельно ничего
отключать не нужно.

## Восстановить канал ВКонтакте

`/api/health` показывает: `vk: 5 User authorization failed: invalid
access_token` — ключ сообщества отозван. Заявки сейчас идут двумя
каналами вместо трёх.

Что сделать:
1. vk.com → сообщество → Управление → Работа с API → Ключи доступа →
   создать ключ с правом «сообщения сообщества».
2. Amvera → Переменные окружения → `VK_TOKEN` → вставить новый.
3. `/api/health` → `vk` должен стать `ok`.

Если после этого появится ошибка 901 — значит с личной страницы ни разу
не писали сообществу. Достаточно написать ему любое сообщение.

## Два приложения — держать в голове

`granat-site` (сайт) и `jarvis-bot` (Джарвис) — РАЗНЫЕ приложения Amvera,
у каждого свой git и свой диск `/data`. Журнал заявок лежит на диске
сайта, и бот прочитать его не может физически. Всё, что им нужно друг от
друга, ходит по сети через `/api/lead/...` — см. «Мостик к Джарвису» в
`app.py`.

Файлы бота (`jarvis_bot.py`, `lead_handoff.py`, `dialog_manager.py` и
прочие) лежат и здесь, и в репозитории `jarvis-bot`. Правка в этом
репозитории САМА В БОТА НЕ ПОПАДАЕТ — файл нужно загрузить в приложение
`jarvis-bot` через его страницу «Репозиторий». Копия здесь однажды уже
отстала от рабочей на десятки строк.

Чтобы мостик работал, в переменных должно быть задано:
- `granat-site`: `WATCH_TOKEN` — любая длинная случайная строка.
- `jarvis-bot`: `SITE_URL` = `https://granat-kmv.ru`, `SITE_TOKEN` = то же
  значение, что `WATCH_TOKEN`.

Пока `SITE_TOKEN` не задан, Джарвис молча работает по-старому — с нуля.

Переменные Amvera подхватывает только при старте приложения: завёл — нажми
перезапуск, иначе получишь `forbidden` на ровном месте.

Проверка мостика без бота, прямо в браузере:
`granat-kmv.ru/api/lead/<номер>?token=<WATCH_TOKEN>` — должна вернуться
заявка. 403 значит, что ключи не совпали или приложение не перезапускали.

Проверка целиком (нужен работающий Telegram): оставить заявку на сайте,
нажать «Продолжить в Telegram» и увидеть «вижу вашу заявку №N» вместо
вопроса про согласие. 09.08.2026 этот шаг не прошли — Telegram лежал.

## Джарвис во ВКонтакте — проверить в бою

Написан (`vk_jarvis.py` в приложении `jarvis-bot`), но живого клиента
через него ещё не проводили. Устройство: отдельный поток рядом с
Telegram-ботом, долгий опрос сообщений сообщества, движок диалога общий —
тот самый `dialog_manager`. Правка промпта меняет оба канала сразу.

Чего в ВК-версии сознательно нет:
- Подтверждения телефона. Во ВКонтакте нет кнопки «поделиться номером»,
  проверить номер нечем. Вместо этого в заявку кладётся ссылка на
  страницу клиента — по ней и отвечаем.
- Апсейл-подарков. Сначала пусть заработает главное.

Переменные приложения `jarvis-bot`:
- `VK_TOKEN` — тот же ключ сообщества, что у сайта.
- `VK_PEER_ID` — id страницы Гульнары (1088419855), куда падает готовое ТЗ.
- `VK_GROUP_ID` — 238836731, можно не задавать: это значение по умолчанию.

Без `VK_TOKEN` модуль молча не запускается, Telegram работает как раньше.

Что проверить: написать сообществу с другой страницы, пройти путь до
конца и убедиться, что ТЗ пришло. В логах `jarvis-bot` при старте должна
быть строка «🔵 ВКонтакте: слушает сообщения сообщества».

После проверки — снять с экрана заявки оговорку «во ВКонтакте отвечает
человек»: она станет неправдой (`follow_up` в `app.py`).

## Обнулить счётчик заявок после тестирования

Сейчас в нумерации сидят тестовые заявки (№11–15). Когда проверки
закончатся, счётчик сбросить, чтобы первая настоящая заявка была №1.

Где лежит: постоянный диск Amvera, каталог `/data`.
- `lead_counter` — сам номер, одно число.
- `leads.jsonl` — журнал событий по заявкам.

Как сбросить: Amvera → granat-site → Данные → удалить `lead_counter`.
Следующая заявка получит №1: `next_id()` заводит файл заново.

Журнал `leads.jsonl` при этом лучше не трогать без нужды — по нему бот
находит клиента по телефону и связывает заявку с перепиской. Если решено
чистить и его, надо понимать, что старые привязки к чатам пропадут.
