## Сменить токен бота «Генерал» — обязательно

09.08.2026 токен несколько часов был виден на открытой странице
`/api/health`: проверка ботов отдавала текст сетевой ошибки как есть, а
Telegram кладёт в него полный адрес запроса вместе с токеном. Утечку
закрыли в тот же день (коммит «Токен бота больше не утекает в /api/health»),
но сам токен считаем скомпрометированным: кто успел его скопировать, тот
может читать заявки.

Что сделать, когда откроется Telegram:
1. @BotFather → `/revoke` → выбрать бота → получить новый токен.
2. Amvera → granat-site → Переменные окружения → `TELEGRAM_BOT_TOKEN`
   (и `ADMIN_BOT_TOKEN`, если заведён) → вставить новый.
3. Открыть `/api/health` и убедиться, что `telegram: ok`.

Старый токен после `/revoke` перестаёт работать сам — отдельно ничего
отключать не нужно.

## Восстановить канал ВКонтакте

`/api/health` показывает: `vk: 5 User authorization failed: invalid
access_token` — ключ сообщества отозван. Заявки сейчас идут двумя
каналами вместо трёх.

Что сделать:
1. vk.com → сообщество → Управление → Работа с API → Ключи доступа →
   создать ключ с правом «сообщения сообщества».
2. Amvera → Переменные окружения → `VK_TOKEN` → вставить новый.
3. `/api/health` → `vk` должен стать `ok`.

Если после этого появится ошибка 901 — значит с личной страницы ни разу
не писали сообществу. Достаточно написать ему любое сообщение.

## Обнулить счётчик заявок после тестирования

Сейчас в нумерации сидят тестовые заявки (№11–15). Когда проверки
закончатся, счётчик сбросить, чтобы первая настоящая заявка была №1.

Где лежит: постоянный диск Amvera, каталог `/data`.
- `lead_counter` — сам номер, одно число.
- `leads.jsonl` — журнал событий по заявкам.

Как сбросить: Amvera → granat-site → Данные → удалить `lead_counter`.
Следующая заявка получит №1: `next_id()` заводит файл заново.

Журнал `leads.jsonl` при этом лучше не трогать без нужды — по нему бот
находит клиента по телефону и связывает заявку с перепиской. Если решено
чистить и его, надо понимать, что старые привязки к чатам пропадут.
