# Порядок дизайнерской работы — обязателен в любом чате

Правило владелицы, 18.08.2026: **«В любом чате, где требуется дизайнер,
навык должен использоваться»**. Не по настроению и не когда вспомнил —
всегда. Правило общее для обеих её организаций; в репозитории студии
лежит такой же файл.

Причина простая. Дизайн «на глаз» выглядит быстрее ровно до первой
правки: цвет подобран пипеткой, отступы на глазок, шрифт «похожий» —
а на второй странице всё это повторить нечем. Навык нужен не ради
красоты, а чтобы решение было **записано и повторяемо**.

## Когда правило включается

Задача дизайнерская, если в ней есть хоть одно из этого:

- сайт, лендинг, страница, экран, форма;
- макет, мокап, прототип, вайрфрейм;
- рекламное объявление, баннер, креатив, сторис, пост-картинка;
- презентация, коммерческое предложение с оформлением;
- карточка товара, обложка, аватар сообщества, шапка;
- печатная продукция: визитка, листовка, меню, сертификат;
- слова заказчика «покрасивее», «посовременнее», «как у них», «вау».

**Слово «дизайн» произносить необязательно.** «Сделай баннер для ВК» —
дизайнерская задача. «Поправь первый экран» — тоже.

## Конвейер: шесть шагов, всегда в этом порядке

Шаг можно пройти быстро, но нельзя пропустить. Пропущенный шаг
всплывает позже и дороже.

### 0. Понять задачу бизнеса

Что человек должен сделать, увидев это? Заказать, позвонить, оставить
телефон, узнать цену. **Нет ответа — дизайна не будет, будет украшение.**
Если задача крупная (новый сайт клиенту) — сначала навык
`marketolog-issledovanie`: сегменты, боли, возражения. Для баннера
хватает одного предложения.

### 1. ДНК — навык `dizajn-dnk`

Откуда берётся система:

| Случай | Что делать |
|---|---|
| Есть референсы от заказчика | снять шесть слоёв по `dizajn-dnk`, при необходимости подробный разбор — навыком `design-dna` |
| Есть фирменный стиль | взять оттуда: логотип, цвета, шрифты. Для «Граната» это `firmennyj-stil/` в его репозитории |
| Нет ничего | подобрать по библиотеке: навык `genjutsu-vkus`, поиск по стилям, палитрам и шрифтовым парам |
| Правим своё | ДНК уже есть: фирменный стиль в `firmennyj-stil/` и тема Tailwind |

Результат шага — **записанные значения**, а не впечатление. Для сайта
это `design/design-dna.json` и `design/design-system.md`; для одного
баннера достаточно строчек в задаче, но цвета и шрифты берутся из уже
существующих токенов, а не подбираются заново.

### 2. Смысл и текст

Структура блоков и настоящий текст — навык `texty-uslug`, для сайта
дополнительно `mnogostranichnik-ru`. **Верстать по тексту-рыбе нельзя:**
настоящий текст всегда другой длины, и половина работы поедет.

### 3. Статика

Собрать всё без единой анимации: структура, типографика, состояния
кнопок и форм, вид на телефоне. Цвета и размеры — только из токенов.

Для сайта это шаблоны Jinja в `zhivoj-sajt/templates/` и стили
Tailwind в `zhivoj-sajt/static/css/`. Цены — из `data/prices.ts`,
в разметку числами не писать.

### 4. Полировка и приёмка — навык `vizualnyj-vkus`

Отдельный проход по списку: воздух, ритм, контраст, иерархия,
состояния, единство иконок и фотографий. Заканчивается чек-листом
приёмки — до показа заказчику, а не после.

### 5. Движение — навык `animacii-veb`

Только когда статика готова и принята. Точный API GSAP —
`gsap-spravochnik`, характер и хореография сложной сцены —
`motion-design`. `prefers-reduced-motion` обязателен.

### 6. 3D — навык `3d-na-sajte`

Открывается, только если на первый вопрос «нужен ли здесь 3D» ответ
«да». Для лендинга местного бизнеса он почти всегда «нет».

## Две проверки перед словом «готово»

```
node .claude/skills/dizajn-dnk/scripts/proverka-tokenov.mjs zhivoj-sajt
```

```
node .claude/skills/animacii-veb/scripts/proverka-dvizheniya.mjs zhivoj-sajt
```
Проверки ловят механику: цвет мимо палитры, разнобой гарнитур,
`style="..."` в разметке, анимацию тяжёлых свойств, движение без
глушения. **Красоту они не проверяют** — это шаг 4.

## Что это значит для рекламных макетов и мокапов

Тот же конвейер, короче:

- **Рекламный макет.** ДНК уже есть — берём фирменный стиль
  из `firmennyj-stil/` (шаг 1 занимает минуту). Дальше текст, статика,
  полировка. Цена и срок — из `data/prices.ts`, руками не писать.
  **Объявили скидку — в том же ответе заводим акцию** в массив `AKCII`
  и пересобираем секретаря: клиент придёт с объявлением, и бот обязан
  знать про эту скидку.
- **Мокап и прототип.** Шаги 0–4 обязательны, шаг 5 пропускается:
  анимация в мокапе скрывает недоделанную статику.
- **Печать.** Это наше производство, и здесь правило жёстче: цвет
  проверяется на бумаге, а не на экране — яркий экранный часто
  печатается грязным. Фирменный стиль существует раньше сайта
  и важнее его. Макет клиента без указанного тиража, бумаги и срока
  в работу не идёт: 16.08.2026 такой заказ ушёл к другим, пока
  считали руками.

## Чего делать нельзя

- **Начинать с картинки, а не с задачи.** Красивый экран, который
  не ведёт к заказу, — это расход, а не работа.
- **Подбирать цвет и отступ на глаз**, когда есть токены.
- **Показывать заказчику черновик с рыбой** — обсуждать начнут рыбу.
- **Ставить шрифты и библиотеки с чужих CDN.** Файлы кладём к себе:
  IP посетителя не должен уезжать на чужой сервер, а сайт собирает
  заявки по 152-ФЗ.
- **Обещать «будет как у Apple».** У них так выглядит не вёрстка,
  а бюджет съёмки и работа команды.
- **Анимировать до готовой статики.** Движение поверх сырой
  типографики маскирует проблему, а не решает.

## Если чат забыл про навыки

Признаки: цвета подбираются в разговоре, отступы называются числами
из головы, анимация появилась раньше вёрстки, про `prefers-reduced-motion`
не сказано ни слова. Лечение одно — вернуться к шагу 1 и пройти
конвейер. Это дешевле, чем сдавать работу, которую нечем повторить.
